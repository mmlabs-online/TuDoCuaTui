# Consult — software-architect — T-019.7 (2026-11-15, read-only)

## Findings
- **F1. `boundary.test.ts` blocks this ticket as written** (`src/features/auth/boundary.test.ts:20-49` forbids `fetch(`, `localStorage`, `api.mmlabs`, `console.` in `src/features/auth`, and any app module mentioning `features/auth`). Replace with a per-file allowlist (R10), don't delete.
- **F2. Resend can't work right after sign-up:** `POST /auth/signup` returns `{id, email, …}` (org-admin-api `app/modules/auth/router.py:97-102`), no `account_id`, no cookie; `verify-email/resend` needs `{account_id}` + cookie → resend only when the device holds `mm_account_id`, else the existing "Đăng nhập để gửi lại email" fallback (props already optional). Unverified users can log in (`/token` → `email_unverified`), so resend belongs on the sign-in path.
- **F3. Sign-in also needs Turnstile:** after 3 failed logins, login → 403 `turnstile_required` (ADR-0004 §8); without a widget the user waits out the backoff.
- **F4. The Turnstile site key belongs to org-admin-api:** pair of its `TURNSTILE_SECRET_KEY`; the widget hostname list and org-admin-api `TURNSTILE_ALLOWED_HOSTNAMES` must include `tudocuatui.mmlabs.online` → a Ming step (new M-item; ticket says `Needs Ming: —`).
- **F5. `/healthz` reports `auth` (`server/app.js:71`) but `detectMode` discards it** (`src/data/mode.ts:24-25`); `opaqueredirect` (expired Access) has no body → `auth` unknown; `detectMode` returns `local` in `DEV` (`mode.ts:43`) → identity path can't run in `pnpm dev`.
- **F6. Wiring:** `useWardrobe` builds `createHttpRepo()` with no token (`useWardrobe.ts:28-31`); photo loader created once on first render only with `getToken` (`:33-37`), unmount → `photos.clear()` → `<App key=…>` under the gate meets T-019.6 obligation (1), mounting App only in `ready` meets (3). `httpAiSettings` is a module singleton without a token (`aiSettings.ts:105`, used `App.tsx:257`) → must become per-App.
- **F7. Referrer:** server sends `Referrer-Policy: strict-origin-when-cross-origin` (`server/http.js:6`); `/verify-email` served by the SPA fallback (`static.js:79-84`); fragments are never in `Referer` and the hash is stripped first → low risk; `server/http.js` is T-019.8's file.
- **F8. Bootstrap deadlock:** M-19 says Ming signs up "from TuDo's sign-up page once T-019.7 is live"; D37 says no release with T-019.1 until Ming has an Identity account; T-019.1 is merged → any release with T-019.7 contains T-019.1 → TuDo's sign-up page can't reach production before Ming has a `sub`. M-20 (verify + join) also happens while production is `auth: access`; join UI is T-019.10.
- **F9. Size:** ~700 product + ~800 test lines across ~18 files (bigger than T-019.11).

## Recommendations
- **R1. `identityClient.ts` (swappable port, A10):** `login({email,password,turnstileToken?})` → `{accountId,email}`; `token(accountId)` → `{accessToken,expiresIn}`; `logout(accountId)`; `signup({email,password,turnstileToken})` → `{email}`; `verifyEmail(token)`; `resendVerification(accountId)`; (T-019.10 adds `listAccounts`, `join`). `createIdentityClient({ baseUrl, app, fetchFn? })`. Cookie-class + login/signup: `credentials:"include"`, `X-MM-App`, JSON; `verifyEmail`: `credentials:"omit"`, no `X-MM-App`, token only in body. One `toAuthError(status, headers, json)` in `errors.ts`: code from an explicit `AUTH_ERROR_CODES` list else `unknown`; `reasons` array filtered to `too_short`/`too_common`; `retryAfterSeconds` from `Retry-After` (parsed, clamped); `TypeError` → `network` (also unreadable cross-origin 500); `app_header_required`/`origin_not_allowed`/`audience_mismatch` → `unknown`; messages never contain a token. Validate response shapes. Constants in `src/features/auth/config.ts`: `IDENTITY_BASE="https://api.mmlabs.online"`, `APP_KEY="tudocuatui"`, `TURNSTILE_SITE_KEY`.
- **R2. `tokenStore.ts`** (`createTokenStore({ client, storage = localStorage, now = Date.now })`): token only in a closure; storage only `mm_account_id` via `accountId.ts` (UUID-shaped or dropped). `getToken(rejected?)`: cached while `now < receivedAt + (expires_in − 60) * 1000` (from receipt, never `exp`); else one shared in-flight `client.token(accountId)`; `rejected` forces refresh only if it equals the current token (10 concurrent 401s → one `/token`). Lazy refresh (timers throttled in background tabs; 401 retry covers sleep/wake). Generation counter on `signOut()`/session loss discards late refreshes. Errors: `session_invalid` clears token + `mm_account_id` and notifies; `not_member`/`email_unverified` notify and keep the account id; `network`/`rate_limited` reject and keep everything. `subscribe(fn)`. `signOut()`: bump generation, clear token, best-effort `logout`, always remove `mm_account_id`. `getToken` stays one stable function (T-019.6 signature).
- **R3. Mode detection:** `probeOnce` returns the parsed body; `detectRuntime()` → `{ mode, auth: "identity"|"access"|null }`; keep `detectMode()` as a wrapper (`mode.test.ts` unchanged). Gate only when `mode === "api" && auth === "identity"`; missing/unknown `auth` → App as today (fails closed via 401). Never fall back to local.
- **R4. Lazy load in `main.tsx`:**
  ```ts
  const verifyHash = takeVerifyHash();             // sync, before detectRuntime(): replaceState first
  const { mode, auth } = await detectRuntime();
  if (mode === "api" && (auth === "identity" || verifyHash !== null)) {
    const { AuthRoot } = await import("./features/auth/AuthRoot");
    render(<AuthRoot app={(p) => <App mode="api" {...p} />} verifyHash={verifyHash} identity={auth === "identity"} />);
  } else render(<App mode={mode} />);
  ```
  `takeVerifyHash` in a tiny non-auth module (`src/lib/verifyFragment.ts`, ~10 lines): on `/verify-email` with a hash, copy it, `history.replaceState(null, "", "/verify-email")`, return the copy (no parsing; `parseVerifyToken` runs in the lazy chunk) → "replaceState before any network call" holds although `/healthz` comes first. `AuthRoot` takes App as a render prop. Local mode: strip the hash, show the app. Recommend the verify flow also runs when `auth === "access"` (public endpoint; unblocks M-20) — Ming decides (Q1).
- **R5. AuthGate states:** `checking` (silent restore when `mm_account_id` exists) · `signed_out {notice?: "signed_out"|"verified"; error?}` · `sign_up` · `blocked {code: "not_member"|"email_unverified"; accountId}` · `error {code: "network"|"rate_limited"|"unknown"; retry}` · `ready {generation}` · `verify {hash}`. Restore: no id → `signed_out` (no network); `session_invalid` → `signed_out` silently; `network` → `error` with retry, keep id. `blocked`: `email_unverified` shows resend; `not_member` shows copy + "Đăng xuất / dùng tài khoản khác" (T-019.10 adds `JoinScreen`; keep `details.join_available`). `ready`: `app({ getToken, onSignOut, onAuthLost })` under `key={generation}`; `getToken = store.getToken` (stable from first render). Sign-out / switch: go to `signed_out` first (unmounts App → `photos.clear()`), then `store.signOut()`; a new sign-in bumps the generation → remount.
- **R6. Bearer + one 401 retry:** `src/data/authFetch.ts` `createAuthedFetch({ fetchFn, getToken?, onAuthLost? })` used by `repo.http.ts` and `aiSettings.ts`; without `getToken` behaves as today; with it, `Authorization: Bearer` only for same-origin `base` URLs (start with `/`, not `//`), keep `credentials:"same-origin"` and `redirect:"manual"`; on 401 retry once with `getToken(staleToken)`; second 401 → `onAuthLost?.()` + `ApiError(401)`; blob bodies re-sendable. `createHttpRepo` takes an options object (`{ fetchFn, base, resize, getToken, onAuthLost }`); `useWardrobe` passes `getToken`; App creates the AI client with `useMemo(() => createHttpAiSettings({ getToken }), [])`; remove the singleton. `photoUrls.ts`: same single retry with `getToken(stale)`. `onAuthLost` → gate `signed_out` with `session_invalid` (no loop).
- **R7. Sign-out UI:** `Header` optional `onSignOut` → icon button only when set; label in `LAYOUT_COPY`.
- **R8. Turnstile:** site key a hard-coded constant in `config.ts` (public by design; R3 ok). Not `VITE_` (would touch `Dockerfile`, `ci.yml`, `release.yml` and `check-image.sh` `VITE_` checks; same key every build); not runtime via `/healthz` (changes the T-019.5 contract). `turnstile.ts` is the only file injecting a script: `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit` once (no SRI; Cloudflare forbids pinning); `render(el, { sitekey, action: "signup"|"login", theme, size: "flexible", callback, "expired-callback", "error-callback" })`; `reset()` after every submit; `remove()` on unmount; script load failure → `turnstileReady=false` + `turnstile_failed` copy. Empty `TURNSTILE_SITE_KEY` → sign-up disabled, slot not rendered (fails closed).
- **R9. `/verify-email` and sign-up:** add `"ready"` to `VerifyState`, `onVerify` on `VerifyEmailScreen`, copy `verify.submit: "Xác minh email"`; POST only on click (double click harmless, 204); `parseVerifyToken` null → `invalid`; token only in the verify component's local state, never rendered/logged; after 204 → `verified`, `onContinue` → gate (restore via `mm_account_id`, else sign-in with notice `verified`). Sign-up reset: `SignUpScreen` `key={status === "sent" ? "sent" : "form"}` drops the password (T-019.11 S4); `onResend` only when an `mm_account_id` exists. Keep `Referrer-Policy: no-referrer` in T-019.8 (its file) and write it into T-019.8's ACs; this plan records AC6's header part as met by T-019.8.
- **R10. Boundary test** per-file: `fetch(` and `api.mmlabs` only in `identityClient.ts`/`config.ts`; `localStorage` only in `accountId.ts`, key `mm_account_id` only; `createElement("script")` only in `turnstile.ts`; `console.` and `sessionStorage` nowhere; outside `features/auth` only `src/main.tsx` via dynamic `import("./features/auth/` (regex asserts no static import).
- **R11. Tests:** `tokenStore` (spies on `Storage.prototype.setItem`, `history.*`, `console.*` — only `mm_account_id` set; single-flight; fake-timer threshold; compare-and-refresh `rejected`; refresh after sign-out discarded); `identityClient` (headers/credentials per call; `toAuthError` with `"__proto__"`, `reasons` string, missing `Retry-After`); `authFetch`/`repo.http`/`aiSettings` (no header without `getToken`; header only on same-origin `/api`; one retry; second 401 → `onAuthLost`); `AuthGate` with a fake client (every state; sign-out order unmount → logout → id cleared; remount on new generation); `verifyFragment` (`replaceState` before any `fetch` spy); `VerifyEmailScreen` `ready` state.

- **R14. ## Risks
- F8 deadlock: TuDo's sign-up can't ship before Ming has a `sub`; if no other registered app hosts sign-up, the cutover stalls — decides whether sign-up/verify must work in `auth: access` mode.
- Without a site key + hostname registration, sign-up is dead and a user with 3 typos is stuck at sign-in until the backoff ends.
- Token in JS memory: XSS exposure wider until T-019.8's CSP; release T-019.7 and T-019.8 together (M-21).
- With Access in front, an expired Access session makes `/healthz` look like `auth: null` → App without the gate, API 401; reload fixes; document in M-21.
- Another tab keeps its token up to 15 min after sign-out elsewhere (A15).
- `pnpm dev` can't exercise identity mode; real verification only at M-21.
- Hotspots `main.tsx`/`App.tsx`; `createHttpRepo` signature change touches every test that builds it.
