## Goal
Every PR is typechecked, format-checked and built automatically, so problems are caught before merge.

## Feature reference
`docs/feature-list.md` F-003. Decisions: `work/decisions.md`.

## Scope
- `.github/workflows/ci.yml` on `pull_request` to `main` and on `push` to `main`:
  `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm format:check`, `pnpm build`, and `pnpm test`
  once F-005 has merged (F-005 adds that step).
- `package.json` scripts: `typecheck` (`tsc --noEmit`), `format:check` (`oxfmt --check`).
- Pin pnpm in CI to the version in `.mise.toml` (10.34.3), for example with a `packageManager` field.
- Normalise line endings to LF (`* text=auto eol=lf` in `.gitattributes`) and run `pnpm format` once,
  so `format:check` passes on Windows checkouts too.
- Draft `.github/risk-tiers.yml` from the High paths in the project `CLAUDE.md`.

## Out of scope
- Branch protection / required checks (Ming sets them in GitHub).
- Running DB tests in CI (F-006 is local; CI is P2).

## Acceptance criteria
- [ ] The workflow runs on PRs to `main` and is green on the ticket's own PR.
- [ ] `pnpm typecheck`, `pnpm format:check` and `pnpm build` pass locally on Windows and in CI.

## Technical notes
- Files: `.github/workflows/ci.yml`, `.github/risk-tiers.yml`, `package.json`, `.gitattributes`.
- Verified on 2026-11-07: `tsc --noEmit` passes, `pnpm build` passes, `oxfmt --check` fails on all 25 files
  locally. The cause is `core.autocrlf=true` (CRLF checkout), not the code. There is no oxfmt config.
- `pnpm build` (`vite build`) does **not** typecheck, so the project `CLAUDE.md` line saying it does is
  wrong. Fix that line in this PR.
- `.gitattributes` is generated by Figma Make (Git LFS rules). Add the `eol` line without touching the rest.
- Locally installed pnpm is 11.5.0, but 10.34.3 is pinned. Make sure the lockfile does not churn.
- Risks: the risk-tier file decides future merge rules, so treat its first version as High (Ming reviews).
