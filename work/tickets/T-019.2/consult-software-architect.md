## Findings
- **F1. Nothing carries an identity today.** `app.js:79-85` gets `{ok, code}` from `access.verify`; `handleApi` gets no user; `items.js`/`photos.js` take `(pool, id, …)`. Tests build the app with `access: null` (`app.db.test.ts:22`, `api.db.test.ts:48,371,374`).
- **F2. Dev "off" mode needs an owner too** (`TUDO_ACCESS_DISABLED=1`, refused in production).
- **F3. The server is typechecked** (`tsconfig.server.json` `checkJs` over `server/**/*.js`) → a JSDoc branded type is enforced by `pnpm typecheck`.
- **F4. Unscoped SQL:** `items.js` `listItems:35`, `listLocations:41`, `getItem:101`; `saveItem:56-71` (location `on conflict (name)` commits even if the item write should be refused; item `on conflict (id) do update` unguarded); `removeItem:116-120`, `wearItem:138-150`. `photos.js` `withLockedItem:98`, `putPhoto:192,220,225`, `servePhoto:265`; DELETE (`:153`) ignores `found` (missing item → 204; AC changes to 404); global `MAX_IN_FLIGHT = 3` (`:15-16, 145`). `servePhoto` already looks up before ETag/304 (`:265-281`).
- **F5. Errors fail closed:** `errors.js:26` 23503 → 404; but 23502 → 400 `invalid_input` (`:4`), so a forgotten `user_id` looks like a 400 — only a guard test catches it.
- **F6. Old image vs new schema:** during the swap, old `on conflict (name)` fails (42P10) and inserts without `user_id` fail (23502). Writes break for the swap; reads work.
- **F7. Release bundling (D37):** no release with T-019.1 until Ming has an Identity account, so T-019.2 will almost certainly ship in the same release (expand + contract back to back). The ticket note "needs T-019.1 released before its contract migration ships" no longer holds; umbrella dependency text differs from `Depends on: T-019.1`.
- **F8. Owner mismatch hazard:** `TUDO_OWNER_SUB: ""` on `migrate` only (`compose.yml:75-76`); T-019.2 adds it to the app. Differing values → empty wardrobe / split ownership; empty app value → app exits 2 after the contract is applied and the old container is gone.
- **F9. AI stays shared until T-019.3** (`ai/store.js`, `tagPhoto.js:12`); guard test must not flag them yet. `initAi` uses `requestAuth: access !== null` (`index.js:55`) — if auth becomes always non-null (incl. dev off), AI would silently switch on in dev without Access.
- **F10. Sweep correctly global** (`photo-sweep.js:84,129`); comment + allow-list entry only.
- **F11. ## Recommendations
- **R1. Request context:** replace nullable `access` in `createApp` with required `auth: { authenticate(req): Promise<{ ok: true, userId: UserId } | { ok: false, code: string }> }` (the T-019.5 shape). `access.js`: `createAccessAuth({ verifier, ownerSub })` returns `ownerSub` after CF verify; `createFixedAuth(ownerSub)` for dev off (non-production only). `app.js` passes `userId` into `handleApi` ctx → data layer and photo handlers; nothing reads a user from body/query/headers (test: body `user_id` ignored). No `TUDO_AUTH_MODE` here (T-019.5). Keep `initAi`'s `requestAuth` = "Access verifier is on" (`accessConfig.mode === "on"`).
- **R2. userId-first params + branded JSDoc type, not `forUser` closures:** `/** @typedef {string & { readonly __brand: "UserId" }} UserId */` in one place (`server/validate.js` or new `server/user.js`); only producer the auth layer (`asUserId(canonicalUuid)`); tests use a helper. Every exported fn in `items.js`/`photos.js` takes `userId: UserId` first (swap/missing fails typecheck). Closures add refactor cost without extra safety; the real risk (missing `and user_id = $n`) is covered by the guard test, composite FKs, RLS. Keep all SQL in `items.js`/`photos.js` for T-019.4's `withUser`.
- **R3. Owner config and exit codes:** `loadAccessConfig(env)` returns `ownerSub` in `on` and `off`; missing/malformed/nil → `AccessConfigError` with constant message (`TUDO_OWNER_SUB must be a valid UUID`) → exit 2. Required in every mode of this slice (tests inject `auth`). Lowercase at the boundary. Move the UUID/nil check out of `migrator.js` into a shared helper (migrator keeps `MigrationError(…, 2)`). `index.cli.test.ts`: Access on + no owner → 2; malformed → 2, value not in stderr; nil → 2; off + no owner → 2.
- **R4. Exact scoping:** `saveItem` location `on conflict (user_id, name)`; item `on conflict (id) do update set … where items.user_id = excluded.user_id returning id`, never `user_id` in SET; zero rows → rollback (no stray location) → `null` → 404. `getItem`/`listItems`/`wearItem` stats on `items_with_stats … user_id = $n`. `removeItem`: scoped lock, Drive refs from scoped `item_photos`, scoped delete; **keep 204 for missing or foreign** (no existence oracle). `wearItem`: insert via `select … where exists (… id = $1 and user_id = $2)` or FK → 404; scoped decrement. Rule: foreign-id response == nonexistent-id response.
- **R5. Photos:** scoped `withLockedItem(pool, userId, itemId, fn)`; `putPhoto` existence check + insert carry `user_id`; DELETE uses `found` → 404 for missing/foreign item (stale photo id on own item stays 204; update tests). `servePhoto` `where id = $1 and user_id = $2`, 304 after lookup. Per-user in-flight `Map<UserId, number>` checked with the global cap before reading the body; increment before the first `await`, decrement in `finally`, delete at 0; same `503 photos_unavailable` + `Retry-After`; suggested 2 per user, global stays 3; resettable/injectable for tests. Drive `appProperties.userId` stays a follow-up.
- **R6. Contract migration:** PG guard (`server_version_num < 150000`); single-owner assertion before writes (rows exist → GUC set and valid; distinct non-null `user_id` across four tables + `ai_settings` ∈ {∅, {GUC}}; empty DB no-op), constant messages; straggler backfill with `updated_at` triggers disabled; `set not null` on four tables (`ai_settings` stays nullable); `unique(user_id, id)` on `items`, `locations`; replace `locations_name_key` with `unique(user_id, name)`; composite FKs (`set null (location_id)`, `set null (parent_id)`, cascades) dropping the four single-column FKs; view location join on `user_id`. Manual rollback in the header.
- **R7. SQL guard test `server/scoping.test.ts`:** scan literals in `server/*.js` and `server/ai/*.js`; any matching `\b(from|into|update|join)\s+(items|locations|item_photos|wear_logs|items_with_stats)\b` must contain `user_id`; allow-list by file + table (`photo-sweep.js`; `migrator.js` if it matches); leave `ai_settings` out of the table list (T-019.3 adds it) rather than allow-listing `ai/store.js`; negative fixture; document per-literal limitation.
- **R8. `check-image.sh` and `compose.yml`:** add `-e TUDO_OWNER_SUB=<fixed dummy v4 uuid>` to the `ACCESS` array (smoke + db-smoke); `expect_exit 2` for Access without owner, malformed, nil; keep the env-prefix check; db-smoke migrate on empty DB needs no owner. Compose: define the owner once and merge into both services (e.g. `x-owner: &owner { TUDO_OWNER_SUB: "" }`) so one release-PR edit sets both; update header. Update `server/README.md`, `.env.example` (name only).
- **R9. Tests:** two-user tests inject a test-only `auth` (header → one of two `UserId`s), never exported. `api.db.test.ts`: list isolation; PUT foreign → 404 and original unchanged (`updated_at` incl.); DELETE foreign → 204, row still present; wear ±1 foreign → 404; photo PUT/DELETE/GET foreign → 404, Drive fake no create/delete; same location name both users. `schema.db.test.ts`: NOT NULL, cross-user FK rejected, location delete nulls only `location_id`, view last column `user_id`. `migrator.db.test.ts`: straggler backfill; two owners → constant-message raise; GUC ≠ owner → raise; empty DB passes. `photo-sweep.db.test.ts`: both users' files kept. `photos.test.ts`: per-user cap rejects A's 3rd while B passes.
- **R10. Keep one M; don't split by default** (migration and code coupled via the locations `ON CONFLICT` target; a split needs a third expand-safe migration and another release; D37 bundles anyway). Fallback seam: T-019.2a (scoping + owner config + guard + cap + image/compose + small migration adding per-user uniques), T-019.2b (contract).

## Risks
- Owner mismatch between migrate and app (F8) → single YAML value + M-18 `select distinct user_id` check; empty app value takes production down after the contract → release-PR checklist must require the value.
- Write failures during the deploy swap (F6), seconds long; document.
- No image-only rollback after the contract (manual down-migration or restore M-18 backup); state in the plan.
- Photo cache across users on a shared browser (`private, max-age=31536000, immutable`); harmless under Access; T-019.6 must fix before identity mode.
- AI stays shared: T-019.5 (depends on T-019.2 only) could enable identity mode while AI is a single row → every user spends Ming's key. Same for T-019.4 RLS before multi-user sign-up.
- Guard test is per literal, not per statement; FK/RLS backstops.
