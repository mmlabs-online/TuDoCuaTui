**Findings**
- `src/components/Modal.tsx` is the only modal primitive. All six users (Editor, AiSettings, Outfits "Hôm nay mặc gì?", Import, Export, Confirm) go through it, so one fix covers all of them. It has a module-level `stack` that already routes Escape to the topmost modal only. Escape is listened for on `window`.
- Backdrop closes on `onMouseDown` when `target === currentTarget`. That is risky for a drag that starts inside a field and ends on the backdrop. It also bypasses Editor's dirty check, but only because the Editor passes `requestClose`, which opens the discard Confirm when dirty. So Escape and backdrop already route correctly through `requestClose`.
- Editor already has `autoFocus` on the name input (line 343). The report says it is not focused in production, so React's autoFocus probably fires but a conflict (or focus left on the opener or backdrop) makes it unreliable. The real fix is to focus explicitly in Modal on mount and not rely on autoFocus. The Editor test "new item focuses the name field" must pass at mount; check whether `autoFocus` also applies to an existing item (it does, since the input is unconditional). For an existing item, focusing the name is acceptable, but on 390px this opens the keyboard. Prefer to focus the name only when `isNew`.
- The Editor's `item.name` h2 and the eyebrow `<p>` give a natural label. Confirm has an `h2` title. No heading has an id, so `aria-labelledby` needs ids (use `useId`).
- `FilterSelect.tsx` wraps the select in a `label`, but the label has no text; the first option text is the only name. Add `aria-label={label}`. `AiSettingsModal`, `OutfitsModal` (line 188) and `ImportPhotosTab` (line 119) also have unlabeled selects. The ticket scopes only the filter selects, so list the others as follow-ups.
- No scroll lock exists. `.modal` has its own `overflow:auto`, but the `body` scrolls behind the backdrop. CSS uses `html:has(.modal-backdrop)` for toasts, so a `:has()` rule is an established pattern.

**Recommendations** (acceptance criteria: expected behaviour, 390px and dark mode, regression tests)
1. Modal markup: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`. Make the title id the Modal's job: Modal generates an id with `useId()` and exposes it, or takes a `labelledBy` prop. Simplest is a required `titleId` prop with the callers' `h2` receiving the same id. Alternative: `aria-label` from copy for modals with no h2. Check each modal has an h2 first. Confirm: use `role="alertdialog"` with `aria-describedby` pointing at the body `p`, since it is a destructive confirm. That is a small, justified extension.
2. Initial focus, in a mount effect in Modal: remember `document.activeElement` as the opener, then focus (a) the element with `[data-autofocus]` or `autoFocus` if present, else (b) for Confirm, the safe cancel button ("Giữ lại"), never the destructive button, else (c) the dialog container with `tabIndex={-1}`. The Editor passes the name input only for a new item. For modals with a long scrollable body (Import, Export), focusing the container avoids scrolling to a lower control.
3. Escape and backdrop: keep the current behaviour. Escape and backdrop route to `onClose`, and the Editor routes through `requestClose`, so dirty edits ask before discarding. Do not make the backdrop silently discard anything. Switch the backdrop from `mousedown` alone to requiring both mousedown and mouseup on the backdrop, so a text-selection drag does not close the modal. ImportModal aborts on Escape already (existing test); keep that. Stacked Confirm on the Editor: Escape closes only the Confirm (existing test, App.test.tsx:405), and focus must return to the Editor control that opened it.
4. Focus trap: Tab and Shift+Tab cycle among tabbable elements inside the dialog (keydown on the dialog, query `a[href], button:not([disabled]), input, select, textarea, [tabindex]:not([tabindex="-1"])`, skip hidden elements). With stacked modals, only the topmost traps, using the same `stack`. Backdrop of the lower modal should be `inert`/`aria-hidden` if cheap; otherwise the topmost-only trap suffices. Also mark the app root `inert` (or `aria-hidden`) while any modal is open, but only if it does not conflict with tests; the trap is the required part.
5. Focus return: on unmount, focus the saved opener if it is still in the document. If the opener was removed (for example the item card was re-rendered, or a delete removed it), fall back to a stable landmark such as the main heading or the toolbar. For stacked modals, the Confirm returns focus to the Editor's button that opened it, then the Editor returns to its own opener.
6. Scroll lock: ref-count open modals. On the first, set `document.body.style.overflow = "hidden"` (or a class `modal-open` with a CSS rule); restore the previous value on the last close. Account for mobile iOS rubber-banding: `overscroll-behavior: contain` on `.modal` is a low-cost addition. No visible change, so it is within "no visual changes".
7. Filter selects: `aria-label={label}` on the `<select>`, in `FilterSelect.tsx`. Labels are already Vietnamese and come from the copy (Trạng thái, Mùa, Vị trí lưu trữ, Màu, Sắp xếp). Keep the first option text as is.
8. Vietnamese names (R6): add any new strings to the existing copy files (for example a `MODAL_COPY` in `src/constants/`, one place per feature) and not inline. The existing modal titles already are Vietnamese. Confirm's `title` and `body` stay prop-driven.
9. Tests: Modal.test.tsx ("renders an aria-modal dialog and traps focus", plus focus return, scroll lock restore, and Escape topmost only); Editor.test.tsx (new item focuses the name field, existing item does not steal focus on mobile); Confirm focuses the cancel button; FilterSelect has an accessible name via `getByRole("combobox", { name: ... })`. Update class-based queries to `getByRole("dialog")` where touched.

**Risks**
- `autoFocus` plus an explicit focus effect can fight; remove one source of truth. Do not remove the Editor name `autoFocus` before the Modal effect is proven in a test.
- The focus trap must ignore `disabled`, hidden and `display:none` elements (Editor has a photo input and conditional sections); a wrong tabbable list causes a dead end.
- Focusing the name input on mobile opens the on-screen keyboard at 390px and can scroll the form; limit to new items.
- Scroll lock with ref counting can leave the page stuck if a modal unmounts abnormally; restore in the effect cleanup.
- Dark mode and 390px: the change adds no visual styling, but the default focus ring on `tabIndex={-1}` container should be suppressed (`outline: none`) since it is not interactive, while the interactive controls keep a visible focus ring in both themes. Verify the focus ring contrast in dark mode.
- Marking the root `inert` could break existing App tests that query behind a modal; keep it optional.
- `Escape` is on `window`, so an Escape typed in an open `<select>` dropdown may also close the modal; accepted, pre-existing.
