# Consult — database-optimizer — F-001 (2026-11-07)

**Findings**
- Environment: `supabase` CLI 3.0.0 via npx. Docker is up, and another project's stack (`supabase_db_calechip` + pg_meta) is already running on the default ports (db 54322; api 54321 and studio 54323 likely). A bare `supabase start` for tudocuatui will fail with a port conflict. This is the main practical risk.
- Init migration (read-only review): expected to apply cleanly on a fresh stack.
  - `pgcrypto` is harmless (the extensions schema is on the search_path); `gen_random_uuid()` is built in anyway.
  - `auth.uid()` defaults and `references auth.users` are fine, because auth migrations run before `supabase/migrations/*`.
  - `insert into storage.buckets (id,name,public,file_size_limit,allowed_mime_types)` is valid on current storage schemas; `storage.foldername()` exists; `create policy … on storage.objects` works from the migration role in current CLI versions.
  - `items_with_stats` with `i.*` and `security_invoker` is fine on PG15+ (the local image is PG17).
  - Low-probability failure: a storage schema change that breaks the bucket insert. `config.toml` `[storage] file_size_limit` is a global cap and does not conflict with the bucket's 10 MiB.
  - No `drop` / down section is needed: `db reset` replays the migration, so it is repeatable.
- The `config.toml` generated by `supabase init` is mostly fine; `db.major_version` defaults to 17 and matches the local image.

**Recommendations**
1. config.toml (AC1)
   - `project_id = "tudocuatui"`. Critical: it names the containers and volumes, and only a different id avoids a collision with `calechip`.
   - Port conflict: either stop the calechip stack, or set unique ports in `[api] port`, `[db] port`, `[studio] port`, `[inbucket] port`, `[db.pooler]`, `[db] shadow_port`, for example 55321/55322/55323/55324/55329. Unique ports are safer (they don't touch the other project's stack). Document them in the smoke test.
   - `[auth] site_url = "http://localhost:8443"` and `additional_redirect_urls = ["http://localhost:8443"]`. `AuthGate` sends `origin + pathname`, so a non-root path needs `http://localhost:8443/**`.
   - Keep `[auth.email] enable_signup = true` and `enable_confirmations = false`, and keep `[inbucket] enabled = true`; local magic-link mail is read in Mailpit/Inbucket at its port. Keep `[storage] enabled = true`; leave `file_size_limit` at 50MiB (the bucket enforces 10 MiB).
   - Do NOT commit any `[auth.external.*]` secret, SMTP password or Twilio fields; leave them as `env(NAME)` placeholders or disabled. `config.toml` has no secrets by default. Do not commit `supabase/.temp/` or `.env`; check `supabase/.gitignore`.
   - Mail settings (`[auth.email.smtp]`, templates) can make `config.toml` High-tier under "mail sending". Note in the ticket that `supabase/config.toml` should be at least Medium in `risk-tiers.yml`.
2. Verification (AC1): `npx supabase start` (with the isolated ports) → `npx supabase db reset`, which should end with "Finished supabase db reset". Sanity check with `npx supabase db lint` or `\dt public.*`. Then `supabase stop --no-backup` to free the ports.
