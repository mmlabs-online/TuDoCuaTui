## Recommendations
- **R1. Flat modules, no `server/auth/` folder.** `server/identity.js`: `AUDIENCE = "tudocuatui"` (constant, A12), `MAX_TOKEN_CHARS = 4096`, `loadIdentityConfig(env)` → `{ issuer, jwksUrl }`, `createIdentityVerifier({ issuer, jwks?, fetch? })`, `createIdentityAuth({ verifier })` → `Auth`. `server/auth.js`: `AuthConfigError`, `loadAuthConfig(env)` → `{mode:"access", access} | {mode:"identity", identity}`, `createAuth(cfg)`, `requestAuth(cfg)` = `mode === "identity" || access.mode === "on"` (closes note 3; update `ai/config.js:22`); move `Auth`/`AuthResult` typedefs here. `index.js` = load → create → `initAi(…, { requestAuth: requestAuth(cfg) })`. Verifier does no DB / `withUser`, no provisioning table (state in the plan).
- **R2. Verifier** (consumers.md 1–11): only `req.headers.authorization`, `/^Bearer ([A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+)$/i`; missing/other scheme → `missing`; > 4096 chars → `too_large` before jose; never query string, cookie or `cf-access-jwt-assertion`. `jwtVerify(token, jwks, { algorithms: ["ES256"], issuer, audience: AUDIENCE, typ: "at+jwt", requiredClaims: ["exp","iat","sub","jti","iss","aud"], clockTolerance: 30, maxTokenAge: 900 })`. Post-checks: `email_verified === true`; `typeof sub === "string"` and `toUserId(sub) === sub` (reject non-canonical/nil → `sub_invalid`); `roles` array with a string `tudocuatui:…` (length > 11) → else `no_role`; optional: `jti` string and `aud` string (not array). JWKS `createRemoteJWKSet(new URL(issuer + "/.well-known/jwks.json"), { cacheMaxAge: 300_000, cooldownDuration: 60_000, timeoutDuration: 5_000, headers: { "User-Agent": "tudocuatui-server" }, [customFetch]: opts.fetch })`, built lazily (no fetch at startup; image start checks run `--network none`); `jwks` injectable (`createLocalJWKSet` in tests). Fixed error enum: `missing`, `too_large`, `malformed` (ERR_JWS_INVALID, ERR_JWT_INVALID), `alg` (ERR_JOSE_ALG_NOT_ALLOWED, ERR_JOSE_NOT_SUPPORTED), `signature`, `expired`, `claim_<iss|aud|typ|iat|nbf|exp|sub|jti>` (from `err.claim`), `unknown_kid` (ERR_JWKS_NO_MATCHING_KEY), `jwks_unavailable` (ERR_JWKS_TIMEOUT, ERR_JOSE_GENERIC, ERR_JWKS_INVALID, codeless errors during lookup), `email_unverified`, `sub_invalid`, `no_role`, fallback `invalid`. Never touch `err.message`/`err.payload` (payload has `email`). Response always 401 `{"error":{"code":"unauthorized"}}`.

## Risks
1. Identity outage takes TuDo down: stale 300 s cache → each `/api` request waits up to 5 s then 401 (deduped). Longer `cacheMaxAge` (≤ 1 h) softens outages but slows key-compromise removal.
2. Unknown-kid cooldown starts only after a successful fetch; while Identity is down each unknown-kid token triggers an attempt (bounded by dedupe + 5 s timeout).
3. Owner mismatch at M-20: if `TUDO_OWNER_SUB` ≠ Ming's real Identity `sub`, empty wardrobe (data intact); M-20 check must confirm his items appear.
4. 401 spam → one `auth_denied` line per request (json-file 10m×3 bounds disk).
5. `/healthz` auth label is public (minor fingerprint).
6. Hard-pinned issuer → an Identity host move needs a code release.
